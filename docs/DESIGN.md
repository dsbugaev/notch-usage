# NotchUsage — дизайн (2026-08-19)

## Задача
При наведении курсора на чёлку MacBook показывать текущий статус лимитов по токенам всех подписок Claude: личный Max (`~/.claude`) и рабочий Team (`~/.claude-work`).

## Почему своё, а не готовое
Проверены готовые (август 2026): claude-notch-tracker (MIT, один аккаунт), TrayToken (closed, локальные файлы, один аккаунт), AgentPeek (платный, один аккаунт), Claude Usage Tracker, TokenEater. Ни один не заявляет поддержку двух профилей `CLAUDE_CONFIG_DIR` одновременно — а это ключевое требование. Своя утилита ~400 строк Swift, полностью аудируема, токены не покидают машину.

## Архитектура
Один файл `src/main.swift` (AppKit + SwiftUI), без Xcode-проекта, сборка `swiftc` в .app-бандл, автозапуск через LaunchAgent.

- **Хавер-детект**: таймер 80 мс сравнивает `NSEvent.mouseLocation` с прямоугольником чёлки (`NSScreen.safeAreaInsets.top` + `auxiliaryTop{Left,Right}Area`). Задержка входа ~0.16 с, выхода ~0.32 с. Никаких разрешений (Accessibility не нужен).
- **Панель**: NSPanel (borderless, nonactivating, поверх всего, на всех рабочих столах), SwiftUI-контент: по строке на каждое окно лимита (сессия 5 ч, неделя, неделя Opus...) с прогресс-баром, процентом и временем сброса.
- **Данные**: GET `https://api.anthropic.com/api/oauth/usage`, заголовки `Authorization: Bearer <token>`, `anthropic-beta: oauth-2025-04-20`, `User-Agent: claude-code/<ver>` (без него — агрессивный 429; версия берётся из `claude --version` на старте). Основной источник — массив `limits` (обнаружен 19.08.2026 вечером через `--raw`): `{kind: session|weekly_all|weekly_scoped, percent, resets_at, scope.model.display_name}` — именно в weekly_scoped живёт разбивка «Fable | All models». Фолбэк — старые плоские ключи (`five_hour`, `seven_day`, ...), любые словари с `utilization`. Имя модели в лейбле — из `display_name` ответа, не хардкод.
- **Токены**: файл `<configDir>/.credentials.json` (если есть) → иначе связка ключей macOS. Личный профиль — запись `Claude Code-credentials`, кастомные — `Claude Code-credentials-<первые 8 hex sha256(развёрнутый путь configDir)>` (алгоритм установлен эмпирически 19.08.2026: sha256("/Users/dima/.claude-work")[:8] = 92b09eaa; сопоставление «по порядку» не работает — в связке копятся мусорные записи от старых профилей). Весь доступ к связке сериализован на одной очереди. Первый запуск — системный запрос «Разрешать всегда» на каждую запись; отказ запоминается до ручного обновления (кнопка ⟳).
- **Подпись и диалоги связки (финальная архитектура, 19.08.2026 вечер)**: разрешение «Разрешать всегда» на практике привязывается к конкретной сборке бинарника — ни стабильный self-signed сертификат, ни доверие ему (add-trusted-cert) этого не изменили, диалоги возвращались после каждой пересборки. Решение: чтение связки вынесено в отдельный бинарь-хелпер «NotchUsage Credentials» (src/credhelper.swift), который собирается один раз, кэшируется в build/ и при обновлениях панели не пересоздаётся (cp -p сохраняет байты и подпись) — разрешения выдаются хелперу однократно и навсегда. Хелпер отдаёт запись только процессу с именем NotchUsage* (проверка родителя через proc_pidpath) и только для сервисов с префиксом Claude Code-credentials. Проверено фактом: пересборка главного бинаря — чтение без диалогов. Подпись остаётся self-signed «NotchUsage Signing» с ad-hoc фолбэком.
- **Обновление**: фоном раз в 5 мин + при наведении, если данные старше 60 с.
- **Конфиг**: `~/.config/notch-usage/config.json` — список аккаунтов (имя + configDir), интервал.

## Ошибки в строке аккаунта
нет учётки / токен истёк — открой Claude Code (401) / доступ к связке ключей запрещён / сеть / HTTP N. Refresh-токен НЕ трогаем: его ротация из стороннего процесса разлогинила бы сам Claude Code.

## Альтернативы, отклонённые
- ccusage-подход (парсинг локальных JSONL): нет официальных процентов лимитов, именно они нужны.
- SketchyBar: инвазивен, заменяет менюбар.
- Локальный кэш лимитов Claude Code: проверено — его нет (транскрипты и конфиги не содержат utilization).

## Риски
- Ad-hoc подпись: после пересборки бинарника связка ключей спросит разрешение заново.
- Эндпоинт неофициальный: может поменяться; парсер динамический, ошибки видны в панели.
- Токен протухает, если Claude Code долго не запускался — панель честно скажет.
